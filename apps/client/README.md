# Birdtie client

Flutter shell for Birdtie V2's Map Workspace + Agent + Sidebar + Inbox architecture. The home map stays mounted while the keyboard, selection and result overlays change. With `BIRDTIE_API_BASE_URL` configured, Agent tasks use the Birdtie API's deterministic public Activity query and signed-in task history. Follow-ups continue the current task; New starts a separate task. Search this area only queries after the user taps the action and carries visible bounds to the API. The full view renders the task's ordered user and Agent messages. Sidebar → Groups lists and directly publishes owner-confirmed Groups, including Groups without an external source link. Signed-in users can save public Place/Activity/Group results and manage them in Sidebar → Saved; unavailable targets reveal no old content. Inbox reads owner-only review and social events. A real People result can start an explicit contact request, and accepted requests open human conversations in Inbox. Without an API URL, Now and Agent show a Chinese service-unavailable state; local Agent demo fixtures remain available only to isolated tests. Agent Updates, semantic Agent matching, and several Quick Action types remain unavailable and are presented as such.

Sidebar → Settings uses the existing Birdtie API to show blocked Account IDs and Profile access grants, unblock or revoke them, edit the Profile, and sign out. It does not expose private target Profiles or keep credentials in the Settings page.

Sidebar → My Activities shows private plans explicitly marked as intentions, not registrations. A signed-in user can add a visible upcoming or ongoing Activity from an Agent result and remove the plan later. Hidden targets reveal no prior content. Public City Seed Activities are never automatically labelled as the user's own participation.

Cities whose map provider is `amap` use the AMap JS API 2.0 on Web when `BIRDTIE_AMAP_WEB_PUBLIC_KEY` and `BIRDTIE_AMAP_SERVICE_HOST` are configured. The latter must be a trusted `/_AMapService` proxy holding the security key server-side; the Web build must never include that secret. Public WGS84 map positions are converted through AMap before display. Native AMap SDK rendering and live Web Key/proxy verification remain outstanding; an unconfigured map shows a list fallback.

## Public city data

### Runtime environment contract

`lib/src/config/birdtie_environment.dart` is the sole Flutter reader of API and public map build defines. `BIRDTIE_ENVIRONMENT` is `development`, `staging`, or `production`; debug defaults to development, while release requires an explicit staging/production value. Local debug may use `http://127.0.0.1` only with a working ADB reverse tunnel. Staging and production require a non-loopback HTTPS API and the relevant platform's Mapbox public token. Android's main manifest grants Internet access; only the debug manifest permits cleartext traffic. The runtime checks the actual configuration before opening the app.

Release builds must go through `tool/build_release.ps1`, which validates the public config file before passing a build seal to Flutter. A direct `flutter build ... --release` without this seal fails during Dart compilation. For a preflight check, run `./tool/build_release.ps1 -ConfigFile .env.release.local.json -Target apk -CheckOnly`; `Target` also accepts `appbundle` or `web`. Copy `release-config.example.json` to that ignored local file and supply real public values. `-CheckOnly` verifies syntax and URL boundaries, **not** Mapbox authorization or service health. The wrapper never prints the public token. The API must also be deployed and validated separately; no staging/production URL, token permission, or signing credential is supplied by this repository.

Set `BIRDTIE_API_BASE_URL` when running the client. The selected City comes from `GET /v1/cities`, its Place list from `GET /v1/cities/{cityID}/places`, and published Activities from `GET /v1/cities/{cityID}/activities`; no device location is requested. Submitting an intent calls `POST /v1/cities/{cityID}/agent/tasks`. The current task router queries real public Activities, Organizations and Places; it handles bounded area search and contextual Activity follow-ups. This is a rule-based lookup, not AI matching. Results with public point-precision coordinates receive map markers. Signed-in Recent tasks load from the owner-only API and rerun against current access rules on restore. Configure the exact client origin in the API's `BIRDTIE_ALLOWED_ORIGINS` for Flutter web.

## Regional maps

The City API selects the map provider and initial display viewport. Aberdeen uses Mapbox. Web and native Android/iOS use the Civu-provided custom style `lookluo/cmth7kwad001p01ssc9kw7kco` in Birdtie-native adapters. Set `BIRDTIE_MAPBOX_PUBLIC_TOKEN` through `--dart-define-from-file=.env.maps.web.local.json` for Web; Static Tiles requires `styles:tiles`. Set `BIRDTIE_MAPBOX_MOBILE_PUBLIC_TOKEN` through `.env.maps.mobile.local.json` for native. Now map pins and Area Pulse counts come from the real viewport-scoped Pulse API after the initial valid map viewport or an explicit area search. If the map cannot initialize, Now shows a separate current-city upcoming Activity list from the public search API. Without an API URL, no demo Activity results are presented. Task results replace them and recenter the camera. Published Place markers only appear for task-matched public point records. The map does not use device location or private EXIF. Mapbox's logo and source links remain visible on the Web map; the native SDK provides its ornaments.

The map lifecycle, marker diffing and camera/search guarantees are defined in [`docs/architecture/MAP-RUNTIME-PERFORMANCE-CONTRACT.md`](../../docs/architecture/MAP-RUNTIME-PERFORMANCE-CONTRACT.md). The Now page behavior and current API capability boundary are defined in [`docs/product/NOW-AGENT-MAP-WORKSPACE.md`](../../docs/product/NOW-AGENT-MAP-WORKSPACE.md). A microphone is omitted until speech-to-text is implemented. Quick Action types without API support stay disabled.

The existing Civu `MAPBOX_PUBLIC_TOKEN` is stored in ignored `apps/client/.env.maps.mobile.local.json` for native setup and has loaded the custom style on an Android phone. It returns 403 on Web Static Tiles because it lacks `styles:tiles`. Create a separate public Web token in the same Mapbox account and place it in ignored `apps/client/.env.maps.web.local.json`. The final app retains Civu's Android package `app.civu.civu_mobile` and iOS bundle ID `app.civu.civuMobile`; Android debug appends `.birdtiepreview` so both apps can be installed. The existing Civu Android AMap Key is in ignored `android/amap.properties` and is usable only when the package and release signing certificate match its registration. Domestic AMap's renderer and Web JS security proxy are still pending. The Civu Web Service Key is server-only. Exact provider console fields, local file paths and platform status are in `docs/architecture/MAP-PROVIDER-CONFIGURATION.md`.

Android release builds require the original Civu signing keystore through `BIRDTIE_ANDROID_STORE_FILE`, `BIRDTIE_ANDROID_KEY_ALIAS`, `BIRDTIE_ANDROID_STORE_PASSWORD` and `BIRDTIE_ANDROID_KEY_PASSWORD`. The build rejects an absent signer or a versionCode at or below the locally installed Civu baseline 2038. Check the highest published Play track before setting a final build number. Do not commit signing material. See `docs/migration/CIVU-TO-BIRDTIE-CUTOVER.md` for the full upgrade gates.

## OIDC login

The web build can begin the Birdtie OIDC flow from Sidebar → Profile when the API reports that an identity provider is configured. The browser keeps the pending PKCE verifier in tab session storage until the redirect returns. The Birdtie Bearer Session is stored through `flutter_secure_storage`; on restart the client checks it with `GET /v1/me` before restoring signed-in state, and removes it after logout or a 401 response. The login callback URL is cleared from browser history before code exchange. Secure storage on web requires HTTPS or localhost.

The Profile surface lets signed-in users create, edit and withdraw own private Moment drafts. The client does not offer a publish control, media input, Place attachment or EXIF handling. An API running with `BIRDTIE_DEV_PHONE_AUTH=1` also offers a local testing login: request a challenge, then use the prefilled `123456` code. No SMS is sent and the phone number is not verified. This test Account is separate from any existing Civu or future verified phone identity. See the API README for the loopback restrictions and migration.

Sidebar → Profile also lets signed-in users edit their display name, bio and public/private visibility. It can publish an owner-confirmed public Intent in the selected City with a manually supplied coarse area and a chosen duration of 1, 3, 7, 14 or 30 days. A published Intent may appear in Agent People results while valid; the owner can also opt into an approximate public map-zone marker, which is derived from the City view rather than device location; each owner can have up to three active Intents. The owner can withdraw it. Switching the Profile to private withdraws active public Intents; editing the display name or bio does not.

Run the client with the API URL set at build time, for example:

```powershell
flutter run -d chrome --web-hostname=localhost --web-port=7357 --dart-define-from-file=.env.maps.web.local.json --dart-define=BIRDTIE_API_BASE_URL=http://127.0.0.1:8080
```

For a browser login using the command above, allow `http://localhost:7357` through the API's `BIRDTIE_ALLOWED_ORIGINS` and set `BIRDTIE_OIDC_CLIENT_REDIRECT=http://localhost:7357/`. Register the API's `/v1/auth/oidc/callback` URL with the provider. Flutter's development port can vary, so keep it fixed when setting the redirect and origin. No issuer or client credentials are included in this repository.

Android and iOS register the exact `birdtie-auth://callback` native redirect. For a mobile API deployment, configure `BIRDTIE_OIDC_CLIENT_REDIRECT=birdtie-auth://callback` and register the separate HTTPS `BIRDTIE_OIDC_REDIRECT_URI=https://<api-host>/v1/auth/oidc/callback` with the provider. The app opens the system browser, stores a five-minute pending PKCE verifier in platform secure storage, accepts only that native callback, exchanges the one-time Birdtie code, checks `GET /v1/me`, and then stores the opaque Birdtie Session in secure storage. A single API configuration has one fixed client redirect; browser and native clients need matching deployment configuration until an explicit multiple-client allowlist is implemented. The server keeps no provider refresh token. The Birdtie Session has an eight-hour absolute expiry and a thirty-minute idle window extended by valid requests; after absolute expiry the user must sign in again. Logout revokes it server-side.

For local development login, the same API URL and allowed origin work without OIDC configuration when the API's development phone flag is enabled. Android Emulator clients can reach the host API with `--dart-define=BIRDTIE_API_BASE_URL=http://10.0.2.2:8080`; a physical device needs an explicit local tunnel such as `adb reverse tcp:8080 tcp:8080` and `http://127.0.0.1:8080`. The API itself remains bound to loopback.

The local development Session is a real server Session and works for authorized mutations, but its fixed test code does not establish ownership of the entered phone number. It must never be treated as production authentication. On Android, the debug app stores the Session in platform secure storage and restores it only while the API still accepts it. Signing out revokes the server Session and removes the local credential.

For the current physical-device debug setup, start the Go API on host `127.0.0.1:3694` using the local database configuration in `apps/api/README.md`, then run `./tool/run_device_debug.ps1` from this directory. The script checks that the saved ignored `.env.maps.mobile.local.json` contains the public mobile token, verifies host `/readyz`, reinstates `adb reverse tcp:3694 tcp:3694`, verifies `/readyz` from the phone, and passes `BIRDTIE_ENVIRONMENT=development` and `BIRDTIE_API_BASE_URL=http://127.0.0.1:3694` to Flutter before install/run. Use `./tool/run_device_debug.ps1 -CheckOnly` to verify the connection without reinstalling. The phone's loopback URL is intentional only with that ADB tunnel; reconnecting the cable may require running the script again. Android debug permits cleartext traffic for this loopback development API; release does not enable it.

The user-provided public token still receives HTTP 403 for required vector tiles. The separately approved existing public token in the ignored mobile config loads the local Android preview map; that does not establish production distribution permission. The mobile config remains saved locally and need not be re-entered for each debug build. API connectivity and map authorization are separate checks.

In debug builds, Settings shows the current API environment, signed-in state and last Agent request's HTTP status, result count, request ID or error. The Agent request sends `X-Request-ID`, which matches the API log entry. The panel and its data collection are guarded by Flutter's `kDebugMode`; release builds do not show it. The diagnostics omit the request text, access token and API URL path/query.
