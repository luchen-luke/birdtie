# V4 活动对话

活动对话独立于双人好友对话、Community 和 Inbox。每个已发布 Activity 最多一个对话；报名不会自动加入对话或创建好友。已确认 `going` 的参加者及当前主办方 Owner/Admin 可以明确加入，页面提示发言名称和消息对其他加入者可见、主办方可管理消息。

每次读取/写入核验活跃 Person、活动可见性、当前 `going` 或四类主办方管理权限、本人对话成员状态，以及与真人主办者的 Block。退出对话或取消/降为 pending 报名即撤销成员资格；重新报名仍需再次主动加入。退群/降权后的管理者仅在仍为 going 参加者时保留普通权限。活动取消或结束后，已加入且仍符合权限者可以读历史，停止新加入和发送。隐藏活动、撤销邀请/成员权限或主体权限失效会阻止读取。

消息只由真人发送，使用客户端 UUID 保证重试幂等。文本最多 2000 字，限每人每分钟 60 条；读取按当前 Block 过滤对方消息。发送者可移除本人消息，当前主办方管理者可移除任何消息，删除为不可恢复的空正文占位并记录审计。参与者可举报当前可读的活动消息，使用独立 `activity_message` 目标；没有运营处置证据时不能称举报已处理。

API 前缀 `/v1/activities/{activityID}/conversation`：GET 状态、POST 明确加入、DELETE 退出；`/messages` GET 最近 100 条并支持 `before` 翻页、POST 发送；`/messages/{messageID}` DELETE 移除。不返回整个报名名单，也不公开参与者历史。服务端资格与消息写入在事务中锁定活动、参加记录和对话成员；数据库取消报名触发器撤销成员资格。消息、加入和管理操作独立审计。

早期客户端采用明确刷新与发送后刷新，不宣称实时推送、已读回执或活动聊天通知完成。正式部署和真实活动仍按发布 Gate 验收。
