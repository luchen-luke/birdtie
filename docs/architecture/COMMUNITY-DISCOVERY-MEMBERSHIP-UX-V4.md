# 社群发现与当前成员管理 V4

日期：2026-10-03；任务：BT-V4-COMM-002。作为 [社群与活动领域合同](COMMUNITY-AND-ACTIVITY-SOCIAL-MODEL.md) 的交互/API 增量，状态与验收只由原 live 队列记录。

## 用户任务与入口

已登录真人从既有社群列表/详情发现公开社群、申请或加入、接受/拒绝邀请、退出；当前 Owner/Admin 从详情“成员管理”查看申请、邀请和名单，检查具体动作，再明确提交。Now 与既有活动直接详情继续保留；社群不是公开活动发现的围墙。界面主要为简体中文，不为本轮创建另一套身份、Agent、数据库或审批账本。

| 页面 | 当前信息与下一步 | 空态/错误/返回 |
| --- | --- | --- |
| 社群列表 | 我管理、我加入、待处理、发现；城市筛选与真实成员状态 | 未登录提示登录；空组解释；刷新；返回原工作区 |
| 社群详情 | 可见说明、当前成员资格、公开活动、加入/申请/撤回/接受/拒绝 | 401/403/404 清除不可见名单；错误可重新读取；返回列表 |
| 成员管理 | 真人管理身份、当前社群、申请/已邀请、成员、可选既有好友 | 好友失败不阻断名单；无匹配权限不显示动作；关闭返回详情 |
| 检查操作 | 操作、目标姓名、所选角色或后果、尚未执行 | 返回修改/取消丢弃预览；确认后读取权威状态 |

## API 与版本绑定

复用 `server.go` 已注册的原 16 条社群路径及领域动作，不新增路由。邀请为 `POST .../invitations`，角色为 `PUT .../members/{memberID}/role`，移除为 `DELETE .../members/{memberID}`，转让为 `POST .../transfer-owner`。

1. 管理调用同一路径、同一请求体，带 `X-Birdtie-Community-Preview: 1`。服务端核当前权限，仅返回绑定 actor/community/target/operation/role 的临时回执；不写成员或审计效果。
2. 客户端展示目标及后果，用户明确确认后调用相同路径/请求体，带 `X-Birdtie-Community-Snapshot: <snapshot>`。不自动预览、批准或重发。
3. 当前真实 Account/Session、Community、本人/目标 Membership、目标 Person、参数均必须匹配。原生更新时间与 `xmin` 是当前保留行的不透明状态/epoch，不是单调业务 revision、历史事件、认知许可或出网批准。
4. 回执最多 30 秒，以 PostgreSQL 时钟验证签发、期限及最终写后期限。预览不是可证明“人已看到页面”的凭据，也不是成功或永久权限。实际提交仍必须通过原领域权限。
5. 缺回执 428，变更/过期/跨会话/错参数 409，身份无效 401，权限 403，不可见 404，错误格式 400，服务缺当前窄能力 503。错误为中文且不返回 SQL/私密正文；HTTP `no-store`。

客户端与旧无回执管理调用的安全门槛同步收紧；旧内部 `SocialStore` actor-ID 方法保留原领域兼容，仅内部使用。注册 HTTP 不能在当前网关缺失时回退旧方法。普通加入/申请/退出使用既有直接动作，不强加管理预览步骤。

## 原生事务与隐私

- 显式 READ COMMITTED/UTC；本人 Account → 当前 Session → 必要目标 Account → Community → Membership。管理动作与审计在同一事务，最后复核 PG 时钟/会话/Account/社群期限/context。
- Community 锁串行当前管理动作；角色和邀请状态以实际当前成员行复核。重复具体审批仅一次生效且一次审计；ABA、撤权、错目标、错角色与过期回执拒绝且无写入。
- HIDDEN 外人即使知道 ID 且 OPEN 也返回 404。受邀者还不是成员，只能接受/拒绝或查看有限说明；撤销邀请后不能复用。仅当前成员读取名单，申请/邀请仅管理者读取。
- 名单姓名复用已有 `birdtie_agent_profile_field_allowed(...,'displayName')`，不把管理角色当作私人姓名许可。姓名字段隐私通过实际独立字段策略控制；普通 Profile 的粗粒度 visibility 不替代字段规则。
- 多个社群允许并存。退出/移除不取消独立活动报名，不创建/解除好友关系；成员数据不写 Profile/Memory、认知授权或模型输入。
- 转让只变更当前成员管理角色；保留原创建人与独立来源权限，具体边界见领域合同第 12 节。

## 中文客户端与持续 UX

应用 UX-CHECK-01/02/03/05/06/07/08/09/10/11/12/13/14/16：先读取当前状态与可选择对象；邀请使用真实既有好友，不索要 UUID 或虚构关系；具体预览与提交分离；切换 Session/主体，包括 A→B→A，丢弃名单、旧提案与迟到响应。未知结果先读权威状态，不盲重发；处理中的重复点击禁用，后端仍以源状态控制副作用。

成员管理使用原 Material 控件、SafeArea、键盘 inset、可滚动内容和至少 48 逻辑像素关闭触达；长姓名/后果可换行，大字不截断主要动作。管理员不提供 owner 转让/管理员角色控制。普通成员保留直接加入/离开/申请操作，不伪装未授权管理入口。
