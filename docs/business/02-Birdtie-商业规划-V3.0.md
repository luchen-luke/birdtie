# Birdtie 商业规划 V3.0

**版本：** 3.0  
**日期：** 2026-09-29  
**状态：** 战略与商业假设，供团队验证；不是已实现能力、签约情况或经营预测。  
**品牌：** Birdtie

## 1. 执行摘要

Birdtie 把城市生活内容、可行动意图与真实连接放进一张可探索的城市网络。用户可以在本地发现，也可以远程探索任何城市；从过去和现在的 Moment、Activity、Journey 与 Place 产生兴趣，将兴趣转成 Intent，找到合适的人或组织并采取现实行动，再由用户决定是否把经历沉淀回个人和城市。

**定位：** Birdtie 是一个由真实生活内容驱动、以城市为索引、以 Intent 和关系促成现实行动的社交发现平台。

**核心原则：** *Every experience can enrich both a person and a place.* 每一次经历，都可以同时丰富一个人和一个地方。

**核心闭环：** Discovery → Desire → Intent → Connection → Activity → Experience/Moment/Journey → Discovery。

首个商业验证方向是以 Aberdeen 为单城样板：组织提供可靠基础信息和活动；在读学生产生当下活动与 Intent；Alumni 提供已发生的城市生活记录和可复用 Journey；新生、访客和远程探索者发现这些内容并采取行动。此处为试点设计，不代表 Aberdeen 学联已签约、城市内容供给已准备或用户需求已验证。

## 2. 问题与机会假设

### 用户痛点

- 新到城市者不知道城市里有哪些真实活动、地点、社群和可一起参与的人。
- 现有内容散落在地图、社交平台、群聊、组织网站和私人相册，历史内容通常在毕业后失去可发现性。
- 普通内容平台容易停留在浏览和收藏；用户需要把“我也想去”转成时间、地点、同行者与行动。
- 组织重复回答基础问题、活动信息容易过期，学生社群每届换人后知识流失。
- 旅行者或异地学生需要跨城探索，但本地推荐产品常以“附近”为默认入口。

### 可检验命题

若 Birdtie 将可信城市骨架、经本人确认的生活记忆、地点与活动关系、Intent、组织入口和受控 Agent 放在一起，用户会更容易从发现走向现实行动；组织会更愿意维护可重复使用的资料；Alumni 会愿意把部分旧经历整理成对后来者有用的内容。

这些仍是产品假设。旧资料未提供经核验的 TAM/SAM/SOM、调研样本、转化数据、签约或收入证据，因此不在本稿编造市场规模或财务预测。

## 3. 目标客户与价值

| 客户/参与者 | 任务 | Birdtie 的价值 | 价值证据 |
|---|---|---|---|
| 新生、国际学生、搬迁者 | 了解城市、活动和同行者 | 城市内容、组织资料、低压力 Intent 与联系 | 首次有用发现时间、活动参与、30 日回访 |
| Alumni / 往届学生 | 留存经历、帮助后来者 | 个人记忆整理与城市贡献入口；旧内容可产生新价值 | 导入完成率、确认发布率、后续收藏/Intent |
| 学联/校园组织 | 组织活动、交接知识、降低重复答疑 | 组织主页、活动发布、城市基础内容与资料维护 | 每周维护率、重复问题减少、报名转化、换届交接 |
| 兴趣社区/活动主办方 | 找参与者、沉淀社区历史 | 公开 Activity/Community/Intent 与活动回顾 | 合格报名、复参与、内容时效 |
| 访客和远程探索者 | 计划跨城出行、了解真实体验 | Explore Anywhere、Past Journey、Place Memory | 保存、复刻、导航/报名/新 Intent |
| 本地场馆与商家（后续） | 获得合适客流与服务线索 | 基于真实地点与活动上下文被发现 | 合格预约/到访线索、续费意愿 |

Alumni 是城市内容的贡献者与知识传递者，不是只服务当前在读用户的流失群体。贡献者标识记录其自愿公开的经验，不暗示机构认证或官方背书。

## 4. 产品资产与定位边界

### Birdtie 的核心资产

1. **城市生活图谱：** Place、City、Community、Moment、Activity、Journey 与人之间的结构关系。
2. **真实行动路径：** 内容产生 Desire，Intent 匹配人/活动，Connection 获得双方同意，Activity 形成现实结果。
3. **历史供给：** 用户确认的历史内容与 Alumni 经验可以支持新用户决策，并产生 Future Utility。
4. **组织供给：** 可验证、带来源和有效期的组织资料、地点、活动与 City Seed。
5. **隐私信任：** 私人 Memory 与公开对象分层，Agent 仅辅助整理，用户确认公开。
6. **Agent 接口：** Personal Agent 理解本人明确授权的偏好；City Agent 基于可见城市数据回答并引用来源。

Birdtie 不以 Agent Builder、无限内容 Feed 或基础模型为主产品；AI 只有在降低整理、查询、匹配和行动成本时才创造产品价值。地图、地点、内容、Journey、Activity、Community 与关系网络构成同一产品系统。

## 5. 冷启动：从一个可维护的城市开始

### City Seed Layer

上线新城市前，先建立最低可用的城市生活骨架：关键 Places、Things to Do、Starter Journeys、Recurring Activities、Communities/Organizations 和当前活动。每条内容带来源、维护者、更新时间和有效期。基础层按平台/组织来源展示，不虚构用户活跃度。

### 三层供给机制

| 供给层 | 责任人 | 内容 | 经营作用 |
|---|---|---|---|
| Platform / Organization | Birdtie 运营、城市合作组织 | 城市基础信息、地点、组织资料、Starter Journey、Recurring Activity | 让新城市在 UGC 稀少时仍然可用 |
| Community | 学联、学校社团、兴趣组织、主办方 | 活动、公告、社区 Journey、活动 Moment、经验说明 | 提供重复发生、可维护的本地供给 |
| User / Alumni | 在读用户、当地居民、往届学生 | Intent、Moments、Experiences、个人 Journey、历史回顾 | 形成真实性、个人差异与代际知识 |

### Aberdeen 样板计划（拟议）

1. 邀请一个组织成为内容合作试点，先录入其当前资料、近期活动、常见问题和维护者。
2. 建立一批具有代表性的地点、日常活动主题和 starter journeys。
3. 邀请在读学生产生当下 Intent、活动与 Moment。
4. 邀请往届学生/Alumni 以“帮后来者了解 Aberdeen”为理由，选择性整理旧相册、导出内容与旅行记录。
5. 让新生、访客及在英国其他城市的学生通过城市页、地图和 City Agent 使用这些内容。
6. 衡量内容是否帮助发现、收藏、Intent、同行联系和实际参加，而不是只看浏览量。

Alumni 贡献可通过主题征集、届别邀请、短时线上整理活动和“我曾在这里生活”故事策展开展。必须让贡献者逐项选择内容、受众、地点精度和署名；不能以默认公开或批量搬运来提高供给数量。组织换届时移交公共资料维护权限，但个人内容始终由作者管理。

## 6. 历史内容的商业价值与信任机制

历史相册、旧社交内容与 Journey 可以减少新城市用户面对的空白，并增加跨城市探索素材。它们的价值不只是回忆：

- 历史 Activity 的照片和回顾帮助用户判断是否关注类似活动。
- 过去 Journey 可被收藏、复刻或用于生成新的旅行 Intent。
- Place Moments 帮助用户看到地点真实体验，而不只依赖官方描述。
- Alumni 经验可延续到新一届学生，减少组织知识随毕业消失。
- 城市内容可被远程探索者发现，扩大城市合作组织的潜在触达范围。

价值成立的前提是内容权利、出处和隐私清楚。私人 Memory 默认不可被城市搜索或 City Agent 使用。Personal Agent 提出整理建议后，作者确认公开对象才进入城市图谱。Birdtie 不依赖未经用户授权抓取第三方平台，也不以私人相册/精确轨迹做广告定向或出售数据。

## 7. 增长与回访循环

### Memory Loop

```text
过去生活 / 城市活动
        ↓ 用户选择导入
私人 Memory → Personal Agent 整理 → 用户确认
        ↓
Moment / Experience / Journey / Past Activity
        ↓ 建立同一对象的 User / Place / City / Community 关系
City Living Layer 更丰富
        ↓
新生、访客、异地用户发现并收藏/提问
        ↓
Desire → Intent → Connection → Activity
        ↓
新的现实经历与自愿内容
        └──────────────→ 下一轮 Memory Loop
```

内容对象只维护一份权威记录，多上下文展示可提升发现面而不复制数据。分享、评论、收藏和加入活动都不自动转为好友关系。增长分析以对象/事件关系衡量，但不把每次地图曝光算作有效增长。

### 核心增长循环

组织维护资料/发布活动 → 用户发现并参与 → 用户自愿发布活动回顾或 Moment → 同伴形成新 Intent 与连接 → 新用户被城市内容吸引 → 组织获得更合格参与者并持续维护。

## 8. 收入模式假设

先证明城市供给和行动闭环，之后按明确价值测试收费。

| 阶段 | 候选收入 | 付费方与价值 | 准入证据 |
|---|---|---|---|
| 封闭试点 | 免费或有限的项目服务费 | 组织试用城市内容维护与活动工具 | 服务范围、人力成本、试点反馈 |
| 组织产品 | 组织工作台订阅、席位/运营工具费 | 学联、学校组织、社区减少重复答疑并持续运营 | 周活跃、节省工时、续用/付费意愿 |
| 活动服务 | 活动工具费或透明的合格线索费 | 主办方获得发现、报名和回访 | 可归因报名、活动供给密度与用户信任 |
| 场馆发现 | 明确标注的推广、预约/到访线索服务 | 地点/场馆触达有兴趣的人 | 合格转化和本地供给质量 |
| 个人增强 | 额外存储、个人旅程整理/协作等可选订阅 | 高频用户获得真实个人工具价值 | 核心社交不被人为限制且付费需求持续 |
| 交易服务（远期） | 可选支付/订单服务费 | 用户和服务方获得交易流程 | 合规、退款/争议处理与客服能力 |

不出售私人 Memory、Intent 原文、精确位置、个人关系图或未公开个人数据。商业推荐需标注，用户可关闭个性化商业推荐。不得让付费曝光伪装成 City Agent 的自然答案。

## 9. 竞争与差异化

| 类别 | 常见核心用途 | Birdtie 的差异方向 |
|---|---|---|
| 社交内容平台 | 内容发布、推荐与互动 | 每条内容可关联城市对象并通往 Intent、联系或活动 |
| 地图/点评产品 | 地点查找、评分和导航 | 城市中人的真实经历、历史 Moment、Journey 和组织活动 |
| 活动平台 | 活动列表、报名与票务 | 活动连接人、地点、社区、活动前后经历和新的 Intent |
| 通用 AI 助手 | 生成回答与个人建议 | City Agent 有真实城市图谱依据；Personal Agent 与公共城市数据在授权边界内协作 |
| 校园群聊/社群 | 当前届沟通和临时组织 | 跨届 Alumni 知识、可搜索城市记忆与结构化行动对象 |

差异化仍需通过留存、行动完成率、组织维护意愿和跨届内容贡献验证，当前不宣称形成网络效应或数据壁垒。

## 10. 指标与验证实验

**北极星候选：每周由发现转成的有效现实行动数。** 需同时跟踪安全指标，避免通过骚扰或低质量活动提高计数。

| 环节 | 指标 |
|---|---|
| City Seed | 每城核心地点/组织/主题覆盖；来源完整率；过期资料比例；组织周维护率 |
| Discovery | 有用发现率、地点/城市页深度、地图/列表使用、跨城探索回访 |
| Desire | 收藏、关注类似活动、Journey 保存/复刻、“我也想做”入口使用 |
| Intent | Discovery→Intent 转化；Intent 有效率、过期/关闭率、回应率 |
| Connection | 请求→接受率、双向会话率、无回应/拒绝/屏蔽率 |
| Activity | 报名和实际参与、重复参与、活动后回访 |
| Memory Loop | Memory 整理启动→确认发布率、历史对象被发现/收藏/复刻/触发 Intent 的比例 |
| 信任 | 举报率、错误地点/日期更正、撤权生效时间、隐私投诉、组织 Agent 转人工率 |
| 单位经济 | 每个有效行动的内容运营、AI、地图、存储和支持成本；组织服务毛利 |

试验优先级：历史 Journey 与纯地点页的行动转化比较；城市页/地图/列表入口对跨城探索的作用；Alumni 定向邀请与普通内容征集的有效贡献成本；City Agent 引用回答是否降低组织重复答疑；活动回顾是否增加后续类似活动 Intent。实验设计要保护隐私，不用私人素材或敏感推断做个性化处理。

## 11. 阶段路线与决策门

| 阶段 | 经营重点 | 进入下一阶段的证据 |
|---|---|---|
| 0. 基础盘点 | 复核旧 Civu 对象/代码/开关/生产状态；确认组织和城市供给负责人 | 数据权属、维护成本、试点范围清晰 |
| 1. Aberdeen 种子 | Places、City Seed、组织资料、近期活动、公开 Moment、Intent/连接闭环 | 用户能由内容到真实行动；安全门槛达标 |
| 2. Alumni Memory Loop | 小规模历史内容征集、私有整理、确认发布、Journey 复用 | 贡献者完成率、授权理解度和后续使用价值成立 |
| 3. 城市产品化 | 组织工作台、City Agent、社区内容维护与换届机制 | 组织持续维护并获得可量化价值，城市内容时效可控 |
| 4. 多城复制 | 第二/第三城市种子工具、通用导入和地点/Journey 模板 | 城市启动成本下降且行动/留存质量保持 |
| 5. 商业验证 | 组织付费、活动/场馆服务、可选个人增强 | 付费意愿、毛利、信任与合规条件同时成立 |

路线按证据推进，不按日历或注册人数自动进入下一阶段。跨城之前要证明 City Seed 的搭建和维护可以重复。

## 12. 主要风险与应对

| 风险 | 商业影响 | 应对 |
|---|---|---|
| 城市内容为空或过期 | 用户首次体验差，City Agent 无可用依据 | 先做有限城市；设维护者、时效与退化展示，不伪造热度 |
| Alumni 不愿导入旧内容 | 历史供给不成立 | 小批邀请、逐项选择、提供整理价值和控制权；不把历史导入设为必需 |
| 历史内容无行动价值 | 仅增加浏览而不改善闭环 | 评估收藏、复刻、关注类似活动、Intent 与参加，不以浏览量判断 |
| 版权/他人隐私争议 | 信任、下架成本与法律风险 | 用户确认权属/署名/受众；他人内容举报与移除；原素材私有化 |
| Agent 错误整理/越权发布 | 用户受损、产品信任下降 | 草稿与发布隔离；位置/日期置信度提示；公开前用户确认；全链路审计 |
| 地图过载/位置泄露 | 体验差和安全风险 | 地图聚合、粗化位置、住宅附近保护、地图与列表替代 |
| 组织换届导致供给中断 | 城市资料失效 | 多维护者、角色交接、资料到期提醒与历史版本 |
| 变现过早 | 破坏用户信任与组织关系 | 先验证自然推荐与组织价值；商业内容单独标注，不出售个人数据 |
| 既有资产状态误判 | 重复开发或迁移事故 | 将源码、feature flag、生产、验收分别盘点后确定复用范围 |

## 13. 关键决策待团队确认

1. Aberdeen 是否作为首个正式城市样板，合作组织与负责人是谁？
2. Alumni 内容征集由谁运营、如何确认照片/文字的发布权和共同参与者隐私？
3. 试点的首要成功指标是有效行动、组织服务价值，还是历史内容循环？建议三者并测，北极星以有效行动为主。
4. 组织工作台何时进入付费测试，哪些服务由 Birdtie 运营人员代管？
5. 首批城市基础内容由平台团队、合作组织还是共同维护？
