## 上线前检查

1. CSSA 负责人核对公开组织名称、身份核验状态、活动标题、当地时间、地点、容量、费用和官方链接；未经确认不得标“已核验”。
2. 用非管理员账号从 Now/Agent 找到该真实活动，打开详情、报名、取消报名，再重启 App 核对状态。组织管理员单独验证编辑、取消与通知。
3. 检查底图、Pin、地图失败时的列表回退、真实 API 响应、最近 24 小时错误日志与待处理举报队列。
4. 与 CSSA 确认原有活动公告渠道继续可用，并演练一次“Birdtie 暂停展示，改用原渠道发准确信息”的沟通流程。

## 活动日值守

独立提醒任务须由部署平台每 5 分钟调用已构建的 `cmd/activity-reminders` 程序，注入与 API 相同的数据库连接配置，采集退出码和 `activity_reminder_run` 日志。非零退出、`status=failed` 或超过 10 分钟没有一次成功运行时，向当日值守人告警并核查数据库/调度器。故障恢复后立即重跑；去重由数据库约束保证。提醒仅在活动开始前两小时内、且尚未开始时生成；如果服务停摆直至活动已开始，不补发误导性的“即将开始”提醒，改由值守人按备用渠道处理。实际调度器、日志访问和告警收件人仍须在部署环境配置并演练。

- 值守人每小时查看 API 健康、查询错误、报名失败、通知失败和待处理举报；活动时间或地点变更时立即与 CSSA 负责人核对后由有权限的管理员更新。
- 学生可在 App 内提交帮助/举报；若 App 或 API 不可用，使用上表确认的备用联系方式。举报仅由获授权的值守人按受限队列处理，避免在群聊传播个人资料。
- 记录故障开始/结束时间、影响范围、请求 ID、处理人和用户可见的纠正信息；不在普通日志中加入完整私密对话或精确位置。

## 暂停与回滚触发

出现错误活动时间/地点、公开泄露私人信息、未经授权的发布/报名、核心路径大面积不可用或无法及时纠正的 P0 故障时，暂停 Birdtie 作为该活动的主要发现/报名入口。值守人先告知 CSSA 负责人，并在原有渠道发布权威更新；停止邀请新测试者。仅由有权限的组织管理员按已核对事实编辑或取消 Birdtie 活动，保留报名和审计记录；不要直接删除数据库行。

若问题来自新客户端或 API 部署，按实际部署版本回退到上一个通过验收的版本，并复查数据库迁移的向前兼容性；不得盲目执行生产 `down.sql`。Civu 原有服务和旧客户端维持可用，Birdtie 的试点切流与旧服务退役分别执行，具体边界见 [Civu 迁移切换规范](../migration/CIVU-TO-BIRDTIE-CUTOVER.md)。恢复前重复上线前检查，并由 CSSA 负责人确认活动事实。
