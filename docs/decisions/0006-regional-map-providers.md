# ADR 0006: Regional map providers and public Geo display

Date: 2026-09-30  
Status: Accepted provider direction; Aberdeen Mapbox Android adapter loaded on a real device. Web token and iOS device acceptance pending. China renderer pending.

## Decision

Birdtie uses Mapbox for overseas Cities, starting with Aberdeen, and AMap for mainland China Cities, as selected by the product owner. The City record explicitly selects its provider and carries a sourced, display-only initial viewport. Provider selection is not inferred from a Place or a user's device location. `008_city_map_viewports.sql` sets Aberdeen to Mapbox and uses the [Aberdeen City Council Town House location](https://www.aberdeencity.gov.uk/AAGM/plan-your-visit/town-house-archives) as a city-centre view anchor. That coordinate is not a canonical City centroid or a new Place.

Birdtie's canonical Place coordinates stay WGS84. Only published Places with `location.precision=point` and a coordinate pair become map markers. `city`, `area` and `none` precision do not produce a precise marker. Map and List use the same selected City, Place query results, provenance and Place ID. A later viewport API must continue to filter publication and authorization before returning map features.

For the Flutter web shell, Mapbox is rendered with `flutter_map` and the [Mapbox Static Tiles API](https://docs.mapbox.com/api/maps/static-tiles/) using 512px tiles and a -1 zoom offset. The selected style is Civu's `lookluo/cmth7kwad001p01ssc9kw7kco`, as explicitly requested by the product owner. Styles API metadata inspection found a normal version 8 style without Mapbox Standard imports, so the style is eligible for Static Tiles. The Civu public token's Static Tiles request returned HTTP 403 with `This API requires a token with styles:tiles scope.` A Birdtie Web token with that scope must be created in the existing Mapbox account. The map shows Mapbox's official logo and linked Mapbox, OpenStreetMap and feedback attributions as required by [Mapbox attribution guidance](https://docs.mapbox.com/help/dive-deeper/attribution/). The client uses public `BIRDTIE_MAPBOX_PUBLIC_TOKEN` at build time. [Mapbox token guidance](https://docs.mapbox.com/accounts/guides/tokens/) explains public scopes and URL restrictions. No token value is stored in source.

The web renderer pins `flutter_map` 7.0.2. Version 8.3.2 introduced a transitive native-resource requirement that failed this Windows host's Flutter web build. Birdtie's new Android/iOS project uses `mapbox_maps_flutter` 2.26.0 and the same Civu custom style URI in a Birdtie-native widget. It draws only public point Places, with tap-through to the shared Place detail. Android map loading was visually confirmed on a Xiaomi Android 16 device using the Civu public token and style. No Place marker or tap-through was available to check because local City Seed has no published Place. iOS map loading still needs device acceptance. The native source is not a copy of Civu's map widget or its state/navigation. iOS minimum deployment target is 14.0 per this SDK version.

AMap's China renderer is a separate adapter. AMap's [JS API setup](https://lbs.amap.com/api/javascript-api-v2/prerequisites) requires a Web JS API key and security configuration; [AMap recommends a server-side proxy for the security code](https://lbs.amap.com/api/javascript-api-v2/guide/abc/jscode). A Web Service key and Android native SDK key serve different platforms. No browser AMap key or proxy is present in the read-only Civu configuration reviewed, and no mainland China City is seeded. Birdtie's final Android `applicationId` is `app.civu.civu_mobile` and iOS bundle ID is `app.civu.civuMobile`, per the product owner's successor-app decision. Debug Android appends `.birdtiepreview` to coexist with Civu. Native AMap Key injection files/manifest entries are prepared but no AMap renderer is present. The web app shows an unavailable state for an `amap` City until its dedicated renderer is configured.

AMap's domestic map coordinate boundary must convert approved WGS84 public marker positions at the adapter edge. Canonical Place geometry, EXIF and overseas Mapbox geometry must never be overwritten with provider coordinates. Conversion and licensing review precede any China marker release.

## Civu reference boundary

Read-only Civu inspection found `MAPBOX_PUBLIC_TOKEN` in `D:\Program\Civu\Civu-client\.env.local`; `AMAP_WEB_SERVICE_KEY` in `D:\Program\Civu\Civu-server\api\.env.local`; Android `android.key` bound to Civu's package/signature; and an iOS AMap Key example, but no actual iOS Key file. Under the product owner's explicit map credential reuse instruction, the selected Civu Mapbox public token, AMap Web Service Key and Android AMap Key were copied into ignored Birdtie-local configuration files, without printing values. The Civu Mapbox token is in a mobile-only local file because it cannot serve Web Static Tiles without `styles:tiles`; a separate URL-restricted Web token is required, and URL-restricted tokens do not work with mobile Maps SDKs. The AMap service key has no Birdtie consumer yet. The Android Key can serve the final app only with Civu's existing registered package and release signing certificate; the preview suffix requires its own Key. The iOS Key must be recovered or registered for the retained Bundle ID. No Civu map widget, signing material, Geo conversion, Place data or private user data was copied. See `docs/architecture/MAP-PROVIDER-CONFIGURATION.md` for exact configuration.

## Remaining work

- Create a Mapbox public Web token with `styles:tiles`, update local configuration, confirm permitted origins and account/style usage, then load a real browser tile. Verify the native SDK style on iOS; Android loading is confirmed but markers/taps require published Place data.
- Provision an AMap Web JS key/security proxy for the China web renderer, a preview Android key for side-by-side debugging, and retrieve/register the iOS key. Implement the AMap adapter with WGS84-to-provider conversion at that boundary.
- Add viewport bounds queries, clustering and pagination as City Seed Place volume grows. The first map displays the current at-most-100 Place query result and no private content.
