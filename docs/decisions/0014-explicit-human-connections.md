# ADR 0014: 显式联系人请求与真人会话

状态：已实现首批 API 与 Flutter 入口，2026-09-30。

公开 People 结果只表示本人确认过的、仍在有效时间窗内的公开 Intent。查看结果不会建立联系人关系。登录用户必须选择一个公开 People 结果并自行填写联系说明，才能发送请求；收件人须明确接受后才建立一对一会话。拒绝、撤回和七天到期均不会建立会话。Agent 不代发请求或消息。

请求归属、决定权限与会话成员身份由 Birdtie Session 确定。发送时检查收件人的公开 Profile、所选 City 的当前公开 Intent、Account 状态和双方屏蔽；接受时重新检查 Account 状态与屏蔽。读取或发送消息也重新检查双方 Account 状态、已接受关系及屏蔽。消息写入的 `speaker_kind` 固定为 `human`。Inbox 事件只含通用标题，不带请求说明或消息正文。单个发送者最多保持十个未到期请求，并在每小时最多发送六十条消息；请求说明和消息正文分别限制为 280 和 2000 字节。

Inbox 显示本人收到与发出的请求，以及可用会话。客户端须由用户主动点击接受、拒绝、撤回或发送；会话使用手动刷新，没有推送或已读回执。消息接口首批返回最近一百条，尚无历史翻页。现有 Block 控件可阻止对方继续读取或发送；举报入口和处置工作台尚未实现，对外开放前须另行完成。开发固定码账号不能证明手机号归属，不能据此将联系人关系称为已验证身份。

此切片不复制 Civu 的社交代码或数据，也不授权 Agent 读取私人消息。未来 Agent 若要辅助起草或汇总会话，需另行设计双方授权和可撤销的数据边界。

## V4 追加决策（2026-10-01）

旧 `scope=conversation` 保留本 ADR 的单次联系/私信同意语义，不因历史申请被接受而建立好友。034 新增用户显式选择的 `scope=friend`：无需城市或公开 Intent，但仍要求对方是活跃 Person 且公开 Profile、双方未 Block；对方接受后创建一条城市无关的双向唯一 Person Tie，不自动创建会话。客户端以中文明确显示两种申请。本人可移除 Tie；Block 同事务结束 Tie 和双方待处理申请，Unblock 不自动恢复好友，重建须再次申请/接受。旧会话在 Block 生效期间不可读写；显式 Unblock 后旧会话可再次使用。Tie 不自动授予 Agent 读取私密资料的权利；Follow 另由后续任务实现。

035 增加每位成员自己的持久已读位置与未读数，不向对方提供已读回执。旧消息的已读状态未知，迁移不把它们标为已读或新未读。客户端显示实际消息后才提交消息 ID，服务端核验成员与 Block 并防止游标倒退。见 [会话模型](../architecture/CHAT-CONVERSATION-MODEL.md)。

V4 好友聊天扩展：接受好友申请后不会自动开私信；任一活跃好友主动点击“发消息”时，服务端核验双方账户、活跃 Tie、Block 和会话归属，复用已有双方会话或创建新会话。好友来源会话在 Tie 移除后不可继续使用；旧一次性私信同意不因好友移除而撤销。Block 仍优先拒绝所有双方私信操作。
