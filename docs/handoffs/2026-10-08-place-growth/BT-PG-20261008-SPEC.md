# BirdTie 地点资源积累与个人 Agent 成长补充需求

版本：2026-10-08 v1.0  
用途：供现有 Codex 队列增量对账、实现和验收  
状态：需求与只读审计结论；不是已经执行的开发结果

## 1 要完成的产品闭环

BirdTie 应把可以合法留存、核实和复用的地点事实沉淀为自己的地点资源，并把用户授权使用过程中形成的明确偏好和有依据的行为证据积累到该用户的 Personal Agent。下次提问时，系统应真正使用这些资源，减少重复联网检索，给出更符合当前需求的建议。用户能看到、纠正和删除自己的记忆，也能在同一个 Now 工作区收藏、查看地图和关联内容。

这包含两条互相配合但不能混合权限的数据链：

1. 公共地点链：许可来源 → 候选 → 核实与去重 → canonical Place → 按字段更新 → 可复用检索
2. 个人成长链：授权事件 → Evidence → MemoryCandidate 或明确偏好 → 验证 → Memory → 相关上下文召回 → 推荐与反馈

无需为每个用户训练模型。模型可更换，Agent 身份、授权和记忆连续保存。所谓成长，必须能在下一次真实请求中观察到可解释、可纠正的效果；存在数据库表或 Memory API 还不能证明该闭环已连通。

用户已澄清：拟收录的是名称、地址、地理位置、营业时间及活动等客观信息，以及 BirdTie 用户自己发布并有权展示的 Moment/Post。外站他人的评论、图片和长篇文字不属于本轮导入范围。客观事实与原创内容不同，但事实来自哪个接口、适用什么合同和数据库许可仍须逐源判断，不能统一保证无条件可存。

## 2 与既有需求的关系

本包补充今天的 Now 首页、统一输入框、语音转文字、加号任务与附件、中文输入、紧凑引用、收藏分享和同图查看需求，不替换那份 30 项 Now 包，也不重新建立 AGE/AIR。

- AGE 继续持有 Profile、Memory、Evidence、Policy 和 Context 的规范
- AIR 继续持有运行时、事件执行、模型网关、工具权限和评估
- Discovery 继续负责真实站内与联网检索及多轮回答
- 当天 Now 包继续负责单一工作区、交互、草稿和呈现
- 本包补足地点资源复用与真实个人成长之间缺失或未验收的连接

所有任务初始状态都是 RECONCILE_REQUIRED，测试为 NOT_RUN。Codex 先与真实仓库及已有队列对账，再沿用已有任务 ID 或追加唯一任务，不把本包数量直接相加为剩余开发量。

## 4 地点库如何形成可持续积累

### 4.1 保存地点与复制供应商结果分开处理

一个真实地点可以拥有 BirdTie 自己的稳定 Place ID。平台可通过商家直接提供、用户明确提交并核实、可合法采集的官方信息和开放许可数据建立地点事实。不同用户的收藏、Moment 和活动可以关联同一个 ID，避免每次创建重复地点。

但用户点了收藏，不会自动改变第三方结果的使用条件。若当前来源不允许保存，需要获取可保存的独立事实或使用允许的引用方式。不得以“后台再搜一次”“改写一句话”“只留客观字段”自动视为已清除原来的合同或数据库使用限制。真正独立的来源取得、核实、许可与记录可以成为新的数据来源；同一受限结果换表名或转成模型摘要不行。

腾讯公开服务条款第 2.9 节包含对搜索结果存储、缓存等使用的限制，第 2.10 节涉及相关权利要求；须核实实际 SearchPro 产品、账户合同、版本、例外和另行授权的适用性。本包不作某次具体保存违法的法律结论，也不把这些条款外推至全部互联网事实。[腾讯公开条款](https://cloud.tencent.com/document/product/301/122448)

默认执行规则：未完成权限核对的供应商结果，不进入新增共享缓存、公共 POI 或可跨用户复用证据。对已有 source_batch、引用、回答及验证产物建立留存审查清单，按实际义务制定处置方案；不要因本包自动删除现有用户数据或破坏历史。

### 4.2 地点身份与字段事实

在现有模型上增补，而不是强制新表名：

- Place：稳定内部 ID、城市/区域、名称与别名、分类、地址、坐标与 CRS、发布状态、合并版本
- PlaceFieldEvidence：字段名、值、来源 ID、取得方式、权利状态、观察/核实时间、适用时间段、过期与刷新时点、冲突状态
- PlaceSource：原始来源链接或允许保存的引用、提供者、许可/合同版本、署名要求、允许操作、保留截止日
- PlaceCandidate：候选实体、现有实体可能匹配项、验证问题与审核状态
- SavedItem：用户、canonical Place 或允许持久化的 pending reference、保存时间、用户备注/集合、可见性
- Event/Activity：独立时效对象，关联 Place，保存时间区间、时区、取消和外部/站内动作边界

名称、地址和坐标通常相对稳定；营业时间、节假日安排、是否临时关闭和活动应更频繁核实。刷新周期由字段、来源许可与产品风险共同决定，可配置并经评估，不在无证据时硬编码“所有信息 30 天有效”。在实现配置前，可把“地址”和“今日开门情况”设为不同类别来测试。

冲突处理：保留必要的独立证据，优先验证当前官方营业信息；不能把任意网页标成官方，不能让模型生成地址覆盖已审核地址。无法消解的冲突明确显示“营业时间待确认”，同时提供允许展示的来源。位置模糊时不要为了显示 pin 猜坐标。

### 4.3 查询路由

每次新问题先判断本地资源是否足以回答：

1. 理解当前意图、目标地点/区域、时间和必要字段
2. 读取有权限、未失效的本地 Place、内容及相关个人上下文
3. 判断目标覆盖、匹配程度、字段缺失、时效与来源可信度
4. 足够时直接回答，可用规则生成，无须为了“像 AI”再调用模型
5. 不足时按许可调用对应来源补证，只补缺失字段或候选；用户明确探索新地点时保留外部发现能力
6. 允许留存的信息再进入候选核实；不能留存的只在许可范围内使用
7. 返回同一 Now 中的答案、紧凑来源、地点卡片与地图关联；来源和地点 ID 不混用

公共许可事实可以跨用户复用，用户私人查询、完整画像、相似问句中的敏感内容不能因此公开。语义缓存命中还必须复查实体、时间、权限、当前任务及事实版本；不能用别人的个性化答案替代自己的推荐。已有 30 秒 projection 期限是授权与结果有效期，不是共享地点缓存期限。

### 4.4 收藏与用户内容的价值

收藏必须产生用户可见、可找回、可取消的结果，作为地点库使用的入口，而不仅作为隐藏推荐特征。支持在 Now 中说“看看我收藏的海鲜餐厅”“把这几处加入周末计划”，把选中地点显示到当前地图。既有 UI 包负责具体布局及交互。

库外地点允许先形成待核实收藏，但保存的字段和引用须有留存权；卡片应显示“已保存，地点待核实”，不能没有持久化就显示成功。后续绑定 canonical Place 保留同一收藏关系，不要求用户重新保存。

公开 Place 可关联用户获准展示的 Moment/Post；私密、朋友可见或已删除内容不能因为关联公开地点就被放进 CityContext。城市公共资源不是用户个人对话和行为的公共归档。300 个用户的问询可增加发现线索与覆盖，但不是每次问询都产生一个新、正确、可合法收录的地点。

## 5 个人 Agent 怎样真正成长

### 5.1 学什么与不学什么

| 用户事件 | 可保存或候选的内容 | 禁止直接认定 |
| --- | --- | --- |
| “记住，我喜欢海鲜，不吃辣” | 经授权的明确偏好与排除项 | 无关的健康或身份原因 |
| “今晚想吃海鲜” | 当前时段意图 | 永久海鲜爱好 |
| “替朋友找披萨” | 当前任务对象与限制 | 本人喜欢披萨 |
| 收藏一家店 | SavedItem 与行为证据 | 喜欢、到访或消费过 |
| 创建济州岛行程 | 计划和日期范围 | 已经出行或同意预订 |
| 报名与实际参加 | 分别记为报名和经验证出席 | 报名必然参加 |
| 发布带 GPS 的图片 | 允许读取的地点候选 | 用户本人到访证明 |
| 取消推荐或纠错 | 该场景的负反馈/明确更正 | 全局永久厌恶所有同类事物 |

以用户可纠正的偏好和当前意图为依据，不做敏感属性推断，不把所谓 Agent 性格变成人格诊断。重复信号需要考虑同源性、相互关联和时效，不能用“每收藏一次加 0.1”伪装统计置信度。输出置信度必须有定义和校准证据；没有校准时可用明确/候选/待确认等可解释状态。

### 5.2 事件到记忆的写入规则

事件携带用户身份、对象版本、来源、用途、同意版本、事件时间与幂等键。Runtime 判断资格，提取器只提出结构化候选，验证器检查来源、范围、敏感性、矛盾、重复、保留期限。模型无权直接更新权威 Profile。

明确“记住”的非敏感偏好可在已授权学习范围内直接保存并给简短可撤销反馈；模糊长期推断保留候选，必要时问一两个问题。不要要求用户审核每次普通搜索，也不要默默把所有聊天永久记入画像。用前台轻量提醒和个人 Agent 管理入口承接控制，避免首页再次堆叠“当前社交意图”“完善我的选择”等面板。

版本变更与遗忘要影响实际检索。删除记忆后，相关索引、候选、推荐快照和缓存必须失效或重建；合法保留的最少审计资料不能继续用于个性化。多设备、后台任务和备份恢复也要执行删除账本，不能复活已撤回数据。

### 5.3 记忆进入真实请求

Context Builder 每轮仅召回当前相关且仍授权的记忆，校验用户和角色，再供本地过滤/排序或经批准的模型上下文使用。外部检索查询默认只含完成任务必要的公共约束，不导出用户姓名、原始私聊或完整画像。

系统应记录可供验收的 evidence trace：使用了哪个 memory_id/version、为何与本轮有关、何种规则排除了候选、用户能否更正。它不是模型的隐藏思维过程。推荐变化必须能由实际传入的上下文或排序条件解释，不能只在 UI 写一句“我懂你”。

### 5.4 主动接收与对外行动

“主动接收”首先落实为筛选、排序、推荐与用户允许的通知。用户控制通知类型、频率、安静时段、地域、屏蔽名单和可发现性。来源新鲜度、内容可见性与社交安全仍须检查。

接受邀请、加入活动、发消息、公开内容或支付会改变外部状态，不能因兴趣吻合而默认执行。需要对应的自治策略、有效授权或确认、动作版本绑定、幂等及结果核对。第一阶段做“找到合适机会并解释，由用户选择”，高自治执行另行验收。人格化 Agent 也不应替用户决定与谁建立关系。

## 6 交付次序

1. 对账、来源权限审查与可观测性先行；并行修复不依赖新能力的既有 UI 问题
2. 做两个可验收纵向切片：允许来源的地点入库与本地复用；明确用户偏好进入下一轮真实推荐并可删除
3. 再扩展行为候选、多事件来源、独立活动刷新与用户开启的主动通知
4. 更高自治的发送、加入和接受行动须单独权限及风险验收，不阻塞前述基本价值

必须接入现有 Runtime 和实际 Now 路径。保留当前已验证的搜索、来源、卡片、地图和 Recent 恢复，不以重构为由全部推倒重写。

## 7 验收与证据要求

### 7.1 两条最小真实场景

地点场景：以可持久化、已核实来源建立一个 Aberdeen 地点 → 首次中文查询返回 canonical Place → 第二个用户询问有效地址时不重复 WSA → 营业时间到期时只补证所需信息 → 库外发现收藏后解析为同一实体 → 转私密的 Moment 不再被另一用户看到。

成长场景：登录用户在 Now 说“记住我喜欢海鲜，不吃辣” → 记忆可查看 → 新会话问“附近有什么适合我的晚餐”时相关记忆实际影响结果 → “替朋友找披萨”不改本人偏好 → 纠正/忘记后下一轮不使用旧偏好 → 创建旅程不记为已经参加 → 收到匹配活动仍需用户决定是否加入。

模拟可以证明分支、权限和调用数；真实服务测试须在已有可验证授权范围内执行并披露预算，不能由本文建立新的付费调用权限。报告分别列 mock、隔离数据库、实际服务、真机和生产结果，不把其中一项冒充其他项。

### 7.2 必须包含的反例

- 同名不同城/分店、坐标 CRS 不一致、不同语言别名、来源冲突、节假日例外
- 无权限保存的上游结果、外部页面提示注入、重复事件、并发相同查询、过期缓存
- 游客/用户 A/用户 B/组织角色切换、内容转私密、用户拉黑、撤回学习与删除记忆
- 为朋友搜索、讽刺或引用别人的偏好、临时要求、负反馈与长期偏好冲突
- 中文输入、英语输入、中英混合、中文语音转写中的否定词和纠正
- 工具结果未知、邀请目标改变、后台重试、重复加入/发消息

### 7.3 不可用作完成证明的材料

需求文档存在、数据库迁移存在、路由可以返回、mock 测试通过、模型输出一段个性化文字，都不能单独证明端到端成长已上线。每个任务记录当前提交、调用入口、持久化证据、下一次召回证据、权限反例和测试结果；无法访问真实环境的部分写 BLOCKED/NOT_RUN。

有限运行报告中的预留金额不是实际账单。成本评估报告必须列 WSA 请求数、模型请求数、令牌/延迟、缓存条件、样本数与分母；账单未取得则 cash_cost=UNKNOWN。个人成长与地点复用完成后也不能自动判定 Closed Pilot Ready，真实账号、供给、提醒、运维、安全等独立门禁继续有效。
