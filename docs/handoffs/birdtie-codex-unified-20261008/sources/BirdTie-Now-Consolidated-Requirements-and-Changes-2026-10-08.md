# BirdTie Now 统一入口与地图工作区需求和修改方案

版本 2026-10-08 v1.0  
用途：交给当前 Codex 开发流程，在自然检查点核对已有实现后分批开发和验收。  
范围：汇总今天的首页与城市、统一输入、语音和附件、来源与卡片、收藏与分享、中文体验及同一地图工作区讨论。本文是需求和修改设计，不是已完成报告。

## 1 本轮结论和执行边界

BirdTie 的 Now 应成为同一个可持续使用的地图工作区。用户通过文字、语音、材料和操作菜单提出需求，在原会话中查看结果、修改草稿并完成收藏、分享或创建；地点、路线、旅程和主题地图在同一 Now 地图中切换。阿伯丁/CSSA 是试点，不构成产品城市或用户边界。

现在首先修复访客默认城市、首页冗余入口、来源占屏和重复按钮，同时建立输入与地图状态基础；随后交付收藏、路线、分享及 Civu 内容能力的完整小切片。基础联网发现不能被庞大的迁移项目阻塞，已可工作的搜索链路要保留并做中文回归。半透明风格不应先于地图、操作和数据链路正确性。

本包不授权新增供应商密钥、付费采购、扩大调用预算、部署、推送、生产迁移或旧服务器退役。不能中断当前 Codex 调试，不执行 reset、revert、stash、clean，不覆盖他人未提交修改。两个工作树并行时先明确文件所有者，数据库、端口、卷和配置隔离，保持一个集成与部署负责人。

30 个本包需求初始均为 RECONCILE_REQUIRED，验收初始均 NOT_RUN。它们不等于需要再新建 30 个开发任务，也不能与既有 42 项 UI Repair、22 项 Discovery、AGE/AIR 等直接相加。已有完成项保留历史，新增差异用关联子任务追踪。

## 3 首页和入口应放在哪里

### 3.1 Now 默认首屏

保留：持续存在的地图、一个城市或目的地选择入口、侧边栏入口、Inbox、唯一底部输入框、必要地图控制。首次可有一条轻量提示，例如“想在阿伯丁探索什么？”；开始输入或已有结果后收起。不要把登录、社交状态、画像完善、范围声明和活动空态同时铺在地图上。

访客可以浏览允许公开访问的地图和检索内容。需要账号的保存、发布或发好友，在具体动作处解释并登录；登录完成恢复原对象与草稿。不能用空个人资料卡阻止用户首次获取价值。

本轮默认城市与定位策略：用户手动选择且可用的探索城市优先，其次恢复有效探索上下文，再使用测试默认阿伯丁。未来正式定位模式启用后，仅在用户未指定城市、定位获准且相应底图可用时采用设备区域；拒权或底图不可用采用明确可见的回退。不得自动声称设备位于回退城市，也不得以回退城市作为导航起点。

### 3.2 入口迁移表

| 现有或提议入口 | 本轮处理 | 正确位置或行为 |
|---|---|---|
| 当前社交意图 尚未开启 | 删除常驻空卡 | 用户明确开启时可用小状态条，编辑在 Agent 偏好或会话 |
| 我的社交近况 | 从 Now 移走 | 个人资料或我的页面；不新增首页大面板 |
| 完善我的选择 | 拆解而非换名保留 | 兴趣到 Agent 偏好，公开范围到隐私，当前查询缺项就地询问 |
| 重新读取本人范围 | 隐藏内部维护术语 | 后台刷新授权范围；失败就地重试，不等于重新读取 GPS |
| 管理我的范围声明 | 保留控制，移出城市选择器 | 设置中的隐私与可发现性，说明对他人可见什么 |
| 线上与其他范围 | 移出目的地列表 | 确需线上活动时作为查询过滤，不是地理城市 |
| 查找线上活动与伙伴 | 普通任务 | Now 输入或与当前问题相关的建议 |
| 这片区域有什么 | 压缩并按需出现 | 地图移动后搜此区域，或轻量探索建议 |
| 当前地图范围内暂无公开活动 | 按对象类型重写 | 查询结果的范围说明，活动空态不覆盖地点结果 |
| 收藏入口 | 可找回而非首页大卡 | 侧边栏我的收藏或 Now 指令；原地图展示 |

“全部在 Now”约束的是任务连续性和地图实例，不是禁止所有弹层。来源详情、精确字段编辑、登录和系统权限可使用就地面板或必要系统流程；关闭后恢复当前工作区。外部逐向导航和原网页由用户明确打开。

## 4 统一输入和执行流程

### 4.1 加号的材料与操作

材料分组：照片/视频、文件、链接、地点。操作分组：收藏地点、发布动态、创建主题地图、规划旅程、创建活动。小屏可用两层轻量菜单，但选择后应回到原草稿。不是让每个菜单项再跳转到一个独立全屏创建页面。

查询活动、加入活动与分享当前对象优先作为当前结果的上下文操作，输入自然语言也能触发。动作菜单和自由输入必须进入同一服务接口与权限链，不能实现两套不同质量的业务。

### 4.2 草稿设计

建议统一 DraftEnvelope 概念，按现有代码适配命名：draftId、type、version、actor、text、materialRefs、entityRefs、recipientRefs、visibility、structuredFields、missingFields、provenance、status、operationId。不能把所有草稿强塞成同一庞大数据库表；使用共享外壳加类型化字段及现有业务对象。

字段必须知道来自用户输入、明确选择、元数据、已授权档案还是模型建议。低确定性地点及时间显式标注待确认。用户可直接修正，不必为一个字段经历多轮对话。默认私人草稿，公共发布和发好友有明确最终动作与预览。

录音只负责输入：录音结束生成原语言文字，用户编辑后点击发送。@ 好友先表示引用，只有明确进入“发给某人”才建立收件人。无论从哪个入口进入，发布内容、收件人或可见性改变都要重新确认相应版本。

### 4.3 业务动作状态

读取任务可展示流式回答及检索进度。写入任务必须区分“已生成草稿”“正在提交”“已完成”“失败”“结果待核对”。结果未知时查询 operationId 的执行结果，不盲目重复发布。成功卡应指向实际持久化对象，不能以模型的一句“已收藏”当作成功。

## 5 来源和地点卡设计

正文只展示能回答当前问题的内容，断言旁使用短来源标签，例如“市立美术馆官网”“来源 2”；尾部提供“全部来源 3”折叠入口。详情可看到完整标题、域名、访问或更新时间、完整 URL 和原文操作。引用压缩只改变呈现，不丢来源关联。

每个回合保存稳定的来源集合；一条来源可支持多个明确字段，不能因为同域名就丢掉不同页面。卡片字段与回答共用事实对象，地址、营业时间等冲突不能静默选择。官方标签需要根据具体站点和页面身份判定，不能由模型自由填写。

地点卡建议保留地点名、必要副标题、简短相关事实与来源标识。点击卡片进入详情面板；根据问题选一个主动作：在地图查看或规划路线。收藏和分享为明确次动作；不同时保留多个实际都打开详情的按钮。视觉标签可以小，点击区域和无障碍名称不能小到难用。

## 6 收藏分享和地图应形成可持续使用的链路

收藏的价值包含：记住地点、在地图找回、按城市或列表整理、私人备注、比较候选、组合路线、生成主题地图、进入旅程和分享。它不是纯推荐训练信号。收藏不自动表示喜欢某类活动，更不能直接写成长期人格结论；Agent 只能在授权目的下使用。

分享先选择实际对象，再选择受众与预览。可分享地点、选定路线、主题地图、旅程或文字附件。与朋友的会话是接收结果的位置，发起动作仍可留在 Now。对外链接必须明确实时引用或快照；权限撤销、过期、原对象删除和后续编辑的效果需一致可解释。

所有业务地图操作汇入 Now：MapWorkspace 保存 conversationId、exploreContext、camera、selectedEntity、visibleLayers、activeRouteOrTrip、panelState、draftRef 和 returnContext。原生地图控制器/组件实例应尽可能复用；真实 SDK 限制下即使需重建，也必须恢复状态且不引入新的业务地图页面。

看别人旅程属于临时查看上下文，不覆盖自己的旅程或永久改变探索城市。主题地图或收藏中的地点可叠加当前任务，但采用明确图层选择和图例。地图上的数字必须说明是地点聚合、活动数量还是路线节点。

## 7 选择性延续 Civu

审查 Civu 的地点解析、收藏、主题地图、旅程、内容媒体、分享权限与数据导出能力；先选择一个最小可执行切片验证，再扩大。复用的是经核验的能力、数据契约和规则，不沿用旧的多页面、多地图跳转方式。

如需要迁移既有用户数据：先确定真实数据源及责任人，做只读盘点、备份和隔离恢复验证，再给出映射、差异、回滚和媒体引用校验。没有验证恢复与明确迁移授权，不触碰生产写入。客户端统一入口改造本身不需要立即搬迁所有历史数据。

## 9 分批执行与交付

1. A 快速可见修复：完成现状映射，修复访客默认城市、首页入口、来源和重复动作。保留现有搜索服务，验证原有链路没有回归。
2. B 统一基础：稳定原地图工作区、唯一输入框、类型草稿、语音、附件、权限和中文输入。Civu 复用审查可并行但不能占用另一工作树正在修改的文件。
3. C 完整操作：优先打通收藏找回、原地图路线、分享预览和发送结果。收藏或分享只做按钮不算切片完成。
4. D Civu 业务切片：按可复用性落地动态、主题地图、旅程和活动；每个都要保存、重新打开及权限验证。不要一次重写整个应用。
5. E 每批及最终回归：布局、输入法、可访问性、弱网、账号隔离、地图状态、语言和写入恢复。E 是持续工作，不应等全包结束才开始测试。

若语音供应商、附件存储或活动接口尚不可用，标记具体依赖与最小需要的用户决定，继续独立的首页、来源和地图修复。不要把后端未接通改写为完成，不要为“通过验收”关闭真实失败测试。
