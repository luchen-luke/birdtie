# Birdtie Now 动态主地图与旅程交互实施规格

日期：2026-10-19，Asia/Shanghai。面向原 Codex 实施会话，接续 `BT-FIX-NOW-UI-001`，不建立替代任务队列。

用户要求 Now 主要展示动态，地点成为动态的关联入口。普通动态、串文和已发布的旅程内容沿同一阅读与评论路径呈现；未出发的私人旅程计划从本次新增的“旅程”按钮找回。保留当前完整首页、原生地图、原联系和通知入口及唯一输入框，完成关联接线后合批编译交付。

本轮最新用户要求覆盖此前“一个 Place 承载多条动态，首页主要显示地点”的呈现规则，以及“首页不新增旅程入口”的旧范围；独立点、真实坐标、稳定身份、读取授权、来源期限和地图连续性继续有效。原型中的样例内容不进入产品数据。

## 用户操作结果

1. 打开 Now，直接看到地图范围内当前获准的动态，能辨认内容摘要、类型和实际发布时间，而非只能看到地点和数量。
2. 点一条动态，在原输入框上方打开轻预览；展开后阅读完整正文、图片或视频、串文各条及评论。串文从被点中的原条目定位，仍可前后连续阅读。
3. 输入框明确显示评论对象，用户可以评论当前动态；点击某条评论的“回复”后，显示明确回复对象。回到 Now 对话时恢复原对话草稿。
4. 点动态中的关联地点，查看这个地点的全部当前可见动态，继续分页，并能返回刚才的动态和阅读位置。
5. 点首页“旅程”，查看自己的计划和可见的旅程；查看未出发计划、调整地点与顺序，或打开已发布旅程内容。查看和出发均不自动公开私人计划。

## 统一呈现与领域身份

| 对象 | 首页与面板呈现 | 权威身份和生命周期 |
| --- | --- | --- |
| 单条动态 | 独立内容 pin、完整内容、评论、关联地点 | 原 Moment ID、revision、受众和媒体许可 |
| 串文 | 各原条目仍是动态；由任一条进入完整当前可见串文，定位被选条目 | 原条目 ID 和权威段序保留，不复制或重编号；串文不自动转成旅程 |
| 已发布旅程动态 | 统一内容外观，增加获准旅程的地点顺序与状态 | 明确的公开内容引用和旅程发布版本；私人计划不能直接充当公开动态 |
| 未发布旅程计划 | “旅程 → 我的旅程”内查看与继续编辑；本人主动选中后可看私人计划地图 | 原 Collection/Journey 与所有权、编辑权限；不自动新增公共 pin 或评论对象 |
| 地点 | 动态中的可点击关联地点，或原搜索/详情入口 | 原 Place ID；列表是该地点的当前可见内容查询，不是新的可评论动态 |

这是展示与入口的统一，不合并 Moment、Journey、Place 的领域写入，也不创建另一套内容、审批或评论真源。Activity、组织、搜索结果等原有合法图层和直接路径继续使用各自实体语义，本轮不删除它们。

## 默认 Now 首页

左上菜单和城市、右上联系和通知、左侧朝北、底部原加号与输入框原位保留，材质和字体复用当前 `NowUiTokens`。默认没有常驻大内容面板，不增加“串文”主导航，不恢复“全部点位”。

新增一个带文字的“旅程”轻量按钮，放在左侧朝北控件下方，避开顶栏、安全区、地图署名和输入框；Android 有效目标至少 48dp。它打开当前 Now 宿主中的旅程面板，不替换菜单、城市、联系或通知。具体间距使用现有布局 token，并以真实当前界面检查。

### 动态地图投影

- 内容层的基本单位改为原动态及其合法地理关系。地图 pin 的选择目标必须包含原 Moment ID 和 anchor/关联 ID，不能只含 Place ID。串文某条在多个地点的投影指向同一原条目，不创建多份动态。
- 普通动态与串文条目同地点、同坐标仍分别存在；不同动态不能被缩成一个地点数量 pin。一个串文内不同条目也不能因相同作者、地点或媒体被吞掉。
- 内容有当前获准媒体时用方形缩略图；没有媒体时用同形状的内容符号。标签优先内容摘要和实际发布时间，可加“串文中的动态”等真实类型说明；地点名称退为关联信息，不以“地点名＋N 条”充当内容身份。
- 原生底图的普通 POI 和地名保留。显式搜索地点或从内容点关联地点，继续打开原地点详情/内容路径；不额外铺满一套 POI 目录。
- 缩小时先减少名称、时间和媒体细节，保留各自基础方点；选中内容保持明显。标签预算、媒体预算与基础对象数分开，不能删除未选动态来避免拥挤。
- 完全重合时保留真实锚点、原对象和稳定叠绘，沿现有对象选择器逐条选择；候选按本轮内容排序列出，不新建聚合实体或数字聚合 pin，不用假坐标、扇形和引线移位。选择器只解决命中消歧，不能成为服务端先合并数据的理由。
- 没有关联地点但有独立、明确获准地理锚点的动态仍显示独立方点。没有合法锚点的内容保留在列表/对话/旅程阅读入口，不猜城市中心、设备位置、EXIF或拍摄位置。

关联地点表示内容与该地点的关系，不证明作者正在那里、曾到访或实际在该处拍摄。

### 最新内容与分页

地图内容与同地点列表必须使用同一明确定义的时间语义。新发布内容按真实首次发布时间降序，稳定 ID 作为同一时间的次序；历史导入内容缺发布时间时，使用服务端已知的历史创建时间并保留该来源语义，不伪造“刚刚发布”。编辑时间与评论时间不冒充首次发布时间，不仅靠 UUID 排序。

已存在内容的新评论不自动把旧正文伪装成新动态。“最新”不等于“未读”，没有权威查看回执就不画未读红点。未加载的时间和计数保持未知。

地图服务端分页、客户端累积读取和现有有界预算保留。到达预算时说明已加载范围并提供继续加载或缩小范围，不能把已加载页说成全城全部内容。媒体预算不减少基础点；成功续页追加，暂时错误不清空仍有效数据。

来源允许的前台续读可以取得新内容，但地图 pan/pinch 不自动改变查询范围。用户阅读中保留选中 ID、阅读位置和输入；有新内容时提供明确刷新提示，不突然跳到另一条或自动更换评论对象。新请求、来源撤回与到期继续按当前生命周期守卫处理，不延长旧许可。

## 同一个内容面板

轻预览位于唯一输入框上方，显示作者、真实时间、内容摘要、获准媒体及关联地点。点击内容或“展开阅读”进入同一宿主的完整阅读，保留地图实例、相机与原顶栏。长内容展开后才使用全宽阅读空间。

完整内容的顺序为正文与媒体、关联地点/串文条目或旅程站点、评论、同地点其他动态。后两部分按需分页展开，避免在轻预览里堆满全部内容。长文本、媒体尺寸未知和评论增量不能把主要操作挤出可达范围。

点击地点芯片后，面板标题明确为地点与“这里的动态”，按当前权限取得完整列表，而非地图 pin 自带的前若干 selector。列表能包含当前内容并标注“正在阅读”；“同地点其他动态”区则排除同一原内容 ID，避免重复。地点有多个关联时先让用户选具体地点，不暗取第一个。

从地点列表再点动态，进入相同内容宿主；返回恢复地点列表的页、滚动位置，随后可返回原动态。地点列表本身不是评论对象，输入框不会发布“给地点的评论”。

串文中的无地点条目仍在整篇出现，不为它补画路线。仅在有权读取的实际地点关系间表达内容顺序；不能补画经过私人节点的路径。顺序线不是导航或真实轨迹；无权内容不泄漏正文、地点、媒体或作者，通过必要状态表达缺口。

### 面板动效

采用“从所选内容点引出轻预览 → 同一面板平滑展开 → 原位收起”的连续过渡，保留稳定外壳和内容身份。候选时长约 220–300ms，展开与收起可中断，从当前动画位置接管；不缩放或模糊整张地图，不跳转成另一张首页。

切换动态更新同一面板；旧动画、读取和媒体解码不能关掉或覆盖新内容。键盘只推动原输入框和内容可用区，不新建地图或第二个输入框。系统减少动态效果时使用短过渡或直接切换；实际参数由当前组件和真机表现确定，不宣称固定帧率。

## 唯一输入框的目标

| 当前状态 | 输入框显示 | 提交目标 |
| --- | --- | --- |
| 原 Now 任务 | 现有 Now 对话提示 | 原 Agent 任务 |
| 原真人会话 | 原收件人提示 | 原 Conversation，不进入 Agent 上下文 |
| 已打开且允许评论的单条动态 | `评论《内容摘要》`，并显示受众语义 | 原 Moment ID 与当前 revision |
| 串文当前条目 | `评论第 N 条`，可检查该条摘要 | 当前被选原 Moment，不伪装成整篇评论 |
| 回复某条评论 | `回复 姓名 · 原评论摘要` | 原内容 ID＋明确 parent/reply-to comment ID |
| 地点内容列表 | 保留并显示原 Now 目标；切列表前的评论草稿仍属原对象 | 不创建地点评论，不自动把旧文字转给 Agent |
| 私人旅程计划编辑 | `编辑我的旅程 · 当前字段/条目` | 原 Journey 编辑草稿；无公共评论 |

打开可评论动态默认切入该动态评论上下文，但不自动弹键盘、不选中旧文字、不把原 Agent/真人草稿带进来。上下文条持续显示目标、受众及“回到 Now 对话”；输入框里的文字不能是用户判断目标的唯一依据。关闭内容或返回 Now 恢复原目标与其原草稿。

草稿至少按账号/工作身份、输入模式、内容 ID、回复对象隔离。切到另一动态时保存旧草稿、恢复新对象自己的草稿；无草稿则为空，绝不搬运旧文字。编辑动态、编辑旅程与评论也分别隔离。旧语音、上传、读取、提交回调需核对目标及草稿修订后才能应用。

评论使用原互动领域的预览、具体版本批准、提交、权限和操作恢复；发送按钮明确表达“发布评论”或“发布回复”。沿用已有策略，不另造审批账本或机械叠加第二套确认。成功回执后才清空对应草稿，失败保留；结果未知核实原 operation，不能换 ID 重发。提交键、键盘动作和可用的语音回填使用同一目标分发。

内容可读不等于可公开评论。未登录、不可评论的本人私密/迁入内容、关闭评论、内容删除或撤权时，显示相应状态并禁止提交；不能悄悄回退成 Agent 发送。删除或失权的回复对象也不能自动改成顶层评论。

### 评论与回复的实际缺口

原 `MomentInteraction` 已有真实平铺评论、分页、发布/删除、预览批准及未知结果恢复。本轮复用其 controller/action/list，并去掉 Now 宿主中的独立评论 TextField，让原输入框承担编辑。

当前接口没有 parent/reply-to 合同；真正的回复属于本轮需要补齐的领域与客户端接线。回复引用内容 ID、父评论 ID、当前版本与资格；读取能表达引用关系，原评论删除/不可见时保留合适的不可用状态。不能只在正文拼 `@姓名` 就声称回复完成，不强制增加多层嵌套布局。

串文的现有评论归属各原 Moment，本轮保留它们。整篇可汇总当前可见条目的评论，但必须标注所属条目，提交仍明确针对当前条目；不把历史评论迁移到一个新串文 ID。

已发布旅程要有明确获准的内容引用及评论载体：复用原旅程发布动态的 Moment，或明确选择某站关联动态，界面显示实际目标。不得显示“评论整个旅程”而偷偷提交给第一站。缺少该关系的当前简易公开旅程不冒充完整旅程动态；由实施方补齐真实发布/引用合同并接线。

## 旅程入口

“旅程”打开与内容阅读共用的 Now 宿主，内部提供“我的旅程”和“可见旅程”，不在首页铺开模式栏。

- 我的旅程包含当前账号有权访问的草稿、未出发计划、进行中和已结束旅程。默认优先展示未出发计划；状态使用权威行程与时区规则，不只凭本机日期猜测。跨城市或无地点的计划也能在列表找回，不以当前地图视野过滤掉自己的计划。
- 可见旅程仅包括当前访问者按发布/分享规则可读的记录，支持实际排序、分页和空态。“所有”是当前有权看到的范围，不是所有人的私人计划。若受当前城市/区域限制，标题显示范围，不能用已知 ID 详情接口冒充发现列表。
- 打开我的计划，能看完整地点、天/站顺序、计划时间和实际状态，继续原编辑流程；本人主动打开该计划或选择“在地图查看计划”后，才进入明确标注“我的计划／仅自己可见”的私人计划叠层。离开时恢复公共发现范围、选择和原草稿，不将私人坐标写入公共缓存。
- 打开已发布旅程内容，采用同样的阅读面板，按实际发布版本展示地点与相关动态，可跳到相应条目。私人预算、成员、住宿、thread legs 等未发布资料不进入公共详情或路线。
- 发布与保存计划是不同动作。计划出发/结束、编辑私人内容或关联公开地点，均不自动发布或更新公开版本；需要发布时继续展示准确受众、内容、地点及版本并由本人明确提交。

当前富 `JourneyDetails` 尚不能公开发布，简单公开 Collection 也没有完成附近/可见旅程发现。本轮要补实际服务与客户端数据接线，不能用静态示例列表、占位按钮或仅查询已知 ID 宣称本入口完成。私人计划列表、公开旅程发现与公开版本是不同接口权限，保持明确。

## 实施与合批交付

原实施根代理先核对本轮需求与现有任务/lease，在原任务内增量登记；只由它维护 live 队列与共用报告。本设计会话只新增本规格和隔离预览，不领取开发任务、不改队列或应用源文件。历史 DONE、失败证据、既有未提交内容和发布门槛保留。

按实际依赖完成一个关联批次：动态主投影与时间/分页 → 原阅读宿主与评论/回复领域接线 → 唯一输入框目标隔离 → 地点内容入口 → 旅程私人计划与可见公开版本 → 面板动效和原首页整合。共享 DTO、权限、DDL 和发布合同先协调精确文件范围，不把整个目录授给并行 worker。

完成接线后统一运行必要的直接单元/widget/接口验证并合批编译；不逐小项全仓测试、全量分析、数据库整检、重复装包或截图。针对实际失败定向修复。沿用正常字号、不录屏、不安排大字号专项及延期的中英混合语音验收。
