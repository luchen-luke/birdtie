# BT-V4-CHT-004 活动对话审计与实施计划

状态：仓库实现与开发验收已通过；2026-10-02。依赖 `BT-V4-CHT-001` 已完成，按 live 队列领取。最终队列状态以 live JSON 为准。

目前 `conversations` 是基于双方已接受 Connection 的双人对话，`conversation_messages`/实体卡合同及本人 Inbox 通知已存在；没有活动多参与者对话的数据表、API 或客户端路径。活动通知的 `target_activity_id` 只是跳转引用，不是聊天。活动参与、Community 成员和 Person Tie 继续独立，不由共同聊天推断好友。

下一步在现有聊天授权与四类活动主办方边界内实现活动对话。需要明确加入对话的操作：报名本身不能自动公开真人参与信息；中文进入提示应解释参与者可见性和主办方的管理权限。读写持续复核活动可见性、活跃身份和参与状态，离开/取消报名失去对话访问；活动取消后的发言与历史读取规则须写入合同并测试。Block、非参与者、待确认报名、受限活动、主办方管理权限与消息撤回须有集成矩阵，不把 Inbox 提醒或一对一对话表直接称为群聊。

实施顺序：合同与增量迁移 → 本人/参与者和主办方服务端授权 → 中文活动详情入口与消息页面 → 一次性库 up/down/reapply、隐私/生命周期测试 → 真机开发验证 → 证据与队列。正式环境与真实活动验收继续受独立 Gate 约束。

## 实施结果

已按 [活动对话合同](../architecture/ACTIVITY-CONVERSATION-V4.md) 实现独立消息与成员表及 049 迁移，六个 API 路径方法，取消报名的成员撤销触发器和私有消息举报目标。确认报名仍须明确同意交流；每次操作复核受众、当前参与/管理关系及 Block。消息重试 UUID、跨房间限流、撤回清空正文、当前主办方管理和事务审计均落地。

中文页面已接活动详情，支持主动加入、读写、手动刷新/翻页、退出、撤回/移除、举报、只读和失去权限。账号变化会隐藏旧历史和草稿，不接受旧身份异步响应；成功退出或移除立即清除本地内容，即使后续刷新失败也不保留可见正文。没有把轮询或 Inbox 当实时聊天。

完整检查及真机证据见 [验证记录](../testing/evidence/activity-chat-2026-10-02/README.md)：隔离 001–049/seed/full Go API/DB、迁移保护/重建、Go vet/build、Flutter analyze/129 tests/debug build 和 Android 16 页面实测均 PASS。只在本地开发库应用 049，不触及正式服务。正式部署、生产身份、真实活动、聊天通知和运营处置未获证据，Closed Pilot NO。
