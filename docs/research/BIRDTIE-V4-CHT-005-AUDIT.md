# BT-V4-CHT-005 社群对话审计

2026-10-02，仓库实现与开发验收通过，最终状态以 live 队列为准。CHT-004 已完成后由 live `next` 立即领取；CHT-001、COMM-001 依赖已 DONE。

现有 Community 是无账号/Agent 的持久社交实体；030 已提供独立 active/pending/invited/left/rejected 成员与 owner/admin/member 角色，公开发现与成员身份独立。活动对话 049 仅属于单一活动，双人对话仅属于明确好友关系；两者不能冒充社群聊天。

实现计划：新增 050 社群对话/明确加入成员/持久消息与成员撤销触发器；服务端每次复核当前活跃真人和有效 CommunityMembership，owner/admin 管理权限随当前角色；pending/invited/外人不可读取。公开发现 API 与可见性不依赖聊天。复用已验证中文交流呈现，提供社群详情入口、同意加入、消息刷新与翻页、撤回/移除、举报、退出；不自动改好友或成员关系。验证私密/隐藏、角色变更、退出/撤销、归档、幂等与 Block，隔离库迁移往返及旧功能回归；最后真机开发验收并记录证据。未完成实现/测试前不得 DONE。

## 实施及证据

050 与独立 `communitychat` 服务实现上述成员边界、消息/幂等/限流、当前角色管理、Block、撤回和消息举报。050 状态更新或删除成员的触发器撤销明确聊天资格，再加入 Community 不自动恢复。公开社群发现沿用原 API 的登录及非成员访问规则，不由聊天加入状态决定。社群归档后聊天读取/写入关闭但记录保留。

活动与社群 UI 复用 `entity_conversation_page.dart`，各自包装器保持不同的实体路径、加入提示、举报目标和中文文案；活动旧流程五组测试保持通过。社群详情新增明确交流入口。处理举报时同时补齐活跃发送人检查，避免举报已被隐藏的停用账号消息。

[详细验证](../testing/evidence/community-chat-2026-10-02/README.md)：独立库 001–050、三份 seed、全量 Go API/DB 与旧 ID、050 有数据/举报禁止回退和空表重建 PASS；Flutter analyze/131 tests/debug APK、Go vet/build PASS；Android 16 非成员发现→加入社群（无对话）→明确加入交流→发送→退出交流（仍为社群成员）→重新加入→撤回→退出社群（聊天撤销）实测。没有正式身份、真实供给、运营处理或部署证据，Closed Pilot NO。
